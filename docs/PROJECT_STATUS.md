## Status as of the last CLAUDE.md revision: guest checkout, confirmation and order lookup are live — admin verification (Milestones 34, 37 and 38), search engine optimization, Docker/production hardening and launch remain

Planning and documentation are **Done** (see [docs/TASKS.md](./TASKS.md)). Implementation has progressed through the foundation group, the full Payload data model, the auth confirmation pass, the last of the legacy route removal, and the entire storefront-data milestone group: Milestones 1 to 33, 33a, 35, 36, 46 to 48a (including Milestones 2a, 13a, 27a and 27b) are **Done** — 44 of 68 milestones. Guest checkout now creates real cash on delivery orders through a server action with server-side pricing, shipping and stock checks (Milestones 33 and 33a, [Architecture Decision Record 026](./DECISIONS.md)); `/order-confirmation` shows the placed order ([Architecture Decision Record 027](./DECISIONS.md)); `/orders` is a rate-limited guest lookup by order number + phone (Milestone 36, [Architecture Decision Record 024](./DECISIONS.md)); out-of-stock products cannot be added or ordered; reviews, coupons, the newsletter form and the promo banner are removed. `Orders.create` is admin-only. The production image (Milestone 49), production compose stack (Milestone 50) and automatic fail-closed migrations (Milestone 52a, [Architecture Decision Record 032](./DECISIONS.md)) are done and verified on real stacks. Milestone 52 is **implemented via a Cloudflare Tunnel** ([Architecture Decision Record 033](./DECISIONS.md): `cloudflared` service, no published ports, production environment validation, IP rate limits trusting only `cf-connecting-ip`) and verified on real stacks with a dummy token, but **launch is not cleared**: still open are validation against a real tunnel and real Cloudflare header behaviour, and an owner decision on the first-admin window, which Milestone 52b has since closed (see below). (Milestone totals in this paragraph have not been recounted.) **Milestone 52b (Turnstile + the pre-launch security batch, [Architecture Decision Record 035](./DECISIONS.md) amended by [Architecture Decision Record 036](./DECISIONS.md)) is implemented with partial verification:** a verified Cloudflare Turnstile token is now REQUIRED to place or look up an order (no degraded path); orders are idempotent (unique `idempotencyKey`); the first admin is created from a secret by the deploy step and Payload's open first-register flow is closed; the running app connects as the restricted `gocart_app` database role; `app`/`migrate` run read-only; and, as an interim mitigation only, the Next.js image optimizer is off and `/_next/image` is closed. It was verified in the authoring sandbox against a real PostgreSQL and a *simulated* Cloudflare; continuous integration then passed all six jobs on commit `95bf3b1` (including the real compose stack and a golden path through the real Turnstile widget and siteverify with Cloudflare's public TEST keys); real keys on the real hostname are checked only by the owner's launch checks. **Milestone 52c ([Architecture Decision Record 037](./DECISIONS.md)) upgrades Next.js to 16.3.8**, closing the framework advisories (`npm audit`: critical 2 → 0); lint now runs through the ESLint CLI because Next 16 removed `next lint`. **Launch is still NOT cleared** — real-key Turnstile checks, a Cloudflare WAF rule, first-deploy checks, backups and health checks remain; see [docs/DEPLOYMENT.md](./DEPLOYMENT.md), "Launch blockers". `.env.example` is updated. The owner's scope-based quality assurance rule is in [.claude/docs/GATES.md](../.claude/docs/GATES.md). Prisma is retired. The dummy `assets/assets.js` dataset and its two Redux slices (`productSlice`, `ratingSlice`) are deleted. A dev Dockerfile exists (its `docker build` step is implemented but not fully verified — see [docs/TASKS.md](./TASKS.md)).

**`lib/payload/products.ts` and `lib/payload/categories.ts`** are the server-side (Local API) data utilities — `getProducts()`, `getFeaturedProducts()`, `getProductById()`, `getTopLevelCategories()`, `getCategoryBySlug()`, `getProductsByCategory()` (with descendant rollup). Server components only; client components hit Payload's public-read REST API instead (`CategoriesMarquee.jsx`, `app/(public)/cart/page.jsx` both do this). Types in both are hand-written rather than generated from `payload-types.ts`. `payload generate:types` **now works** (unblocked 2026-08-26 — see [docs/CHANGELOG.md](./CHANGELOG.md)) and its output confirms the hand-written mirrors are accurate; switching these files over to the generated types is still open and not yet owned by a milestone.

**Every storefront route reads real Payload data**: `/` (Milestone 23), `/shop` (Milestone 24), `/product/[id]` (Milestone 25), `/category/[slug]` (Milestone 27a), `/categories` (Milestone 27b), and `/cart` (fixed as part of Milestone 28, not a separate milestone — see below). The category marquee (Milestone 27) and the product-page breadcrumb (Milestone 27a) are real links. `/orders` is the guest order lookup (Milestone 36) — there is no account system to key an order list off of, so it takes an order number plus the phone number used when ordering. `"Best Selling"` is an **admin-curated `isFeatured` flag**, not a computed ranking ([Architecture Decision Record 022](./DECISIONS.md)) — there is no sales or review data to rank by. Search on `/shop` is a real Payload query (Milestone 29, [Architecture Decision Record 025](./DECISIONS.md)). **Checkout is real** (Milestones 33 and 33a): "Place Order" calls a server action that validates input and derives prices, shipping, totals and status server-side, rejects out-of-stock lines, and writes the order; `Orders.create` is admin-only (Architecture Decision Record 026 amended Milestone 13).

**Milestone 28 surfaced and fixed a real, already-live bug, not just a cleanup task**: `/cart` had been resolving line items against a Redux slice populated only from the dummy dataset, so it silently dropped every product added from a real product page since Milestone 25 shipped — "Add to Cart" appeared to work, but the cart always rendered empty. Fixed by fetching real products via REST instead of carrying the fix into a later milestone. See [MIGRATION_PLAN.md](./MIGRATION_PLAN.md)'s Milestone 28 entry for the full account of this and four smaller gaps Milestone 28 also had to absorb (none of which were in its original file list).

**Milestone 27a hit a genuine Next.js 15 App Router limitation, not a bug in this code**: a `loading.tsx` file on `/category/[slug]` made `notFound()` return HTTP 200 instead of 404 (confirmed by isolation testing — `loading.tsx`'s Suspense boundary flushes the response status before the awaited page component can call `notFound()`). `loading.tsx` was deliberately omitted from that one route as a result; full details are in `MIGRATION_PLAN.md`'s Milestone 27a entry. `/categories` has no such conflict (no `notFound()` path) and keeps its `loading.tsx` as originally scoped.

**Admin-only auth is confirmed end to end** (Milestones 20 and 21): Payload's `/admin` is the only authenticated surface in the application — no middleware, no auth dependency, no leftover `isAdmin`/`isSeller` bypass, and no customer-facing route that requires or fakes a login. The dead "Login" button is gone from the storefront navbar.

**No more multi-vendor routes exist anywhere in the app** (Milestones 15, 18 and 26): `create-store`, `shop/[username]`, `pricing`, and `loading` are all deleted, their two dead Footer links are gone, and `ProductDescription.jsx`'s dead "view store" link to `/shop/[username]` is removed.

**Payload collections and the Settings global now exist and are registered in `payload.config.ts`**: `Users` (admin-only auth), `Media` (local-volume uploads), `Categories` (two-level hierarchy, stable slugs), `Products`, `Orders` (guest checkout, line items, cash on delivery, full status enum), and the `Settings` global (shipping/contact config). Access control is set per Milestone 13: public-read/admin-write on `Products`/`Categories`/`Media`, admin-only create/read on `Orders` (guests create orders through the server action, not the collection API — Architecture Decision Record 026, which amended Milestone 13's original public-create). `/admin` now serves a real, collection-backed admin panel, not the collection-less shell from Milestone 3.

## Useful context for AI agents (original wording)

- The original app was a **multi-vendor marketplace** (`app/store/*` vendor dashboard, `app/admin/approve`/`app/admin/stores` vendor approval, a `Store` model in the now-deleted `prisma/schema.prisma`). The target product is **single-store** — [Architecture Decision Record 006](./DECISIONS.md) is Accepted. That legacy surface is fully **removed** (Milestones 14 to 17, 19, all Done) — if you see any of those paths, something has gone wrong; they should not exist. Treat any doc or comment implying single-vs-multi-vendor is still open as stale.
- **TypeScript is established** (Milestone 2a, Done) — `tsconfig.json` with `moduleResolution: "bundler"` (changed from `node` at Milestone 3 to resolve Payload's package `exports`), `allowJs: true`. New files are `.ts`/`.tsx`; existing `.jsx` is never opportunistically converted.
- **Admin auth is wired**: the `Users` collection (`collections/Users.ts`, Milestones 6 and 7) is Payload's built-in auth, the only authenticated role in the system. No Clerk/NextAuth, no customer or vendor auth.
- Currency symbol is `Rs. ` via `NEXT_PUBLIC_CURRENCY_SYMBOL` in `.env.example` (fixed from the original `$`). Full PKR formatting — comma grouping, decimal handling — is still open and belongs to Milestone 55 (not yet started; the exact convention is discussed in [docs/PROJECT_SPEC.md](./PROJECT_SPEC.md)).
